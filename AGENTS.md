# AGENTS.md — Руководство для агентов и разработчиков

## О проекте

Скрипты автопилота для мода **kOS 1.6** (Kerbal Space Program). Язык — **KOS Script**
(файлы `.ks`). Проект решает две задачи:

1. **Посадка ракеты на безатмосферное тело** (`land.ks` и его фазы) — ТЗ в `promt.txt`.
2. **Операции на орбите и перелёты** (`ascent.ks`, `orbit_to.ks`, `tb.ks` — transfer to body,
   `align_plane.ks`, `change_inclination.ks`, `deorbit_phase.ks`).

Проект работает внутри игры: запустить или протестировать код вне KSP + kOS невозможно.
Проверка изменений — только статический анализ и аккуратный ревью синтаксиса KOS 1.6.

## Структура файлов

### Entry points (самостоятельные скрипты)
| Файл | Назначение |
|---|---|
| `land.ks` | Главный скрипт посадки. Параметры: `landLat`, `landLng`, `maxSlope` и др. |
| `ascent.ks` | Запуск с КЕРБИНА: Q-limited gravity turn, старт ступеней, выход на орбиту. |
| `orbit_to.ks` | Вывод на целевую орбиту (Ap/Pe/наклонение). |
| `tb.ks` | Transbody injection: поиск окна, расчёт и выполнение манёвра к другому телу. |
| `align_plane.ks`, `align_inc.ks`, `change_inclination.ks` | Коррекция плоскости/наклонения орбиты. |
| `exec_node.ks` | Простое исполнение маневровой ноды `targetNode` (см. `exec.prompt`). |
| `debug.ks`, `dis.ks`, `dis_orb.ks` | Мелкие утилиты/заготовки. |

### Библиотеки и модули фаз (вызываются через `run` / `RUNONCEPATH`)
| Файл | Назначение |
|---|---|
| `utils.ks` | Общие функции проекта (валидация чисел/векторов, `removeNodes` и т.п.). |
| `m_lib.ks`, `math.ks`, `orbit_lib.ks` | Математика, орбитальные формулы. |
| `calc.lib.ks` | Библиотека расчётов (формат `.lib.ks`). |
| `stg.ks`, `dis.ks` | Старт ступеней, сброс обтекателей. |
| `find_landing_site.ks` | Градиентный поиск ровной площадки (по состоянию, в несколько вызовов). |
| `deorbit_phase.ks` | Деорбита: фаза 1 наклонение, фаза 2 гашение горизонтали, фаза 3 коррекция. |
| `suicide_burn.ks` | Непрерывное финальное торможение («suicide burn»). |
| `horizontal_brake.ks` | Один шаг гашения горизонтальной скорости (используется из `land.ks`). |

### Boot / деплой
- `boot/copy.ks` — запускается с диска корабля (disc 0): копирует/компилирует нужные
  `.ks → .ksm` на disc 1 в зависимости от `SHIP:STATUS` (LANDED/SPLASHED/PRELAUNCH — ascent-набор,
  иначе — landing-набор). При добавлении нового модуля не забудьте добавить `fill("имя")`.

### Спецификации (не код!)
- `promt.txt` — ТЗ на посадку (4 фазы: horizontal → freefall → suicide → final).
- `transfer.prompt` — спецификация `tb.ks`.
- `exec.prompt` — спецификация `exec_node.ks`.
- `chat.txt` (~3 МБ) — лог переписки/черновик. **Не индексировать, не менять, не использовать
  как источник истины.**

## Стиль кода (обязательно, из `promt.txt`)

- Ключевые слова языка — **нижним регистром**: `function`, `until`, `set`, `parameter`, `if`,
  `lock`, `compile`…
- Константы окружения — **ВЕРХНИМ регистром**: `BODY`, `SHIP`, `TARGET`, `ORBIT`, `VELOCITY`.
- Комментарии и сообщения пользователю — на русском.
- Разделители блоков — строки вида `// ==== ... ====` (см. заголовки существующих файлов).
- Код должен быть компактным («место на диске кончилось»): общий код выносить в функции/модули,
  дублирование устранять.

## Правила kOS 1.6, нарушение которых ломает полёт

1. **`@lazyglobal`**: сейчас только `utils.ks` начинается с `@lazyglobal off.` (он обязан
   объявлять все переменные через `parameter`/`local`/`define`); остальные модули —
   `@lazyglobal on.` (align_plane, deorbit_phase, orbit_lib, orbit_to, tb). Entry points
   (`land.ks`, `ascent.ks`, `suicide_burn.ks`, …) директиву не имеют — действует lazyglobal ON.
   Новые библиотеки предпочтительно писать с `@lazyglobal off.` и следить, чтобы в них не
   было неявных глобальных присваиваний.
2. **Зарезервированные имена**: нельзя называть переменные именами встроенных функций
   (`r`, `v`, `q`, `d`, `e`, `n`, `s`, `p`, `sin`, `cos`, `tan`, `arccos`, `sqrt`, `list`, …) —
   ошибка «Not allowed to SET a name that will clobber or hide the BUILTIN_FUNCTION».
3. **SAS и LOCK STEERING конфликтуют**: `SAS` можно включать только после `unlock steering.`
   (и наоборот). Смена режима руления — всегда парой `unlock steering. / set sas to ...`.
4. **Разворот по инерции**: ракета не поворачивается мгновенно; курс не должен «скакать» —
   плавные отклонения от вертикали, запас времени на разворот перед включением двигателя.
5. **Перемотка времени** (`time warp`) разрешена только когда: двигатель выключен, ракета
   развернута в нужную сторону и не крутится (`ANGULARVELOCITY` ≈ 0).
6. **Лимит CPU**: не более ~10000 циклов за кадр — тяжёлые вычисления (градиентный поиск
   площадки) делать пошагово, сохраняя состояние между вызовами.
7. **Фазы посадки определять условиями в `until`**, а не булевыми флажками (см. ТЗ).
8. Целевая скорость касания — **−2 м/с** по вертикали, 0 по горизонтали; в момент касания:
   `unlock steering.` → `set sas to true.` → газ 0 → lights on.
9. Учитывать **TWR** (меняется после отделения ступеней) при расчёте момента suicide burn и
   ограничений тяги; вертикальная тяга на суборбитальной фазе не должна превышать `BODY:GS`.

## Известные проблемы (учитывать при правках, не «чинить» молча в unrelated PR)

- `land.ks` помечен в истории как «Land broken» — фазы работают нестабильно.
- `orbit_lib.ks` / `calc.lib.ks`: подозрительная формула Кеплера (путаница ARCCOS/SIN, единицы).
- `land.ks`: переход в фазу `final` может быть недостижим (нет гистерезиса условий `until`).
- `horizontal_brake.ks` частично дублирует `deorbit_phase.ks` — кандидат на объединение.
- Мёртвые/экспериментальные файлы: `dis_orb.ks`, `debug.ks` — не расширять без причины.

## Как вносить изменения

1. Правьте минимальное число файлов; новый общий код — в `utils.ks` (или отдельный модуль +
   `RUNONCEPATH("имя").` у потребителей и `fill("имя")` в `boot/copy.ks`).
2. Перед коммитом — самопроверка стиля: ключевые слова в нижнем регистре, `BODY`/`SHIP` в верхнем,
   нет зарезервированных имён переменных, SAS/STEERING не включены одновременно.
3. Для новых скриптов-фаз сверяйтесь с `promt.txt` / `*.prompt` — они являются спецификацией.
4. Коммиты — маленькие, с описанием на русском или английском (что и почему изменено).

## Чего в проекте нет (не удивляться)

- Нет тестов, CI, линтеров — kOS-скрипты проверяются только запуском в игре.
- Нет README; функция файлов описана в шапках каждого `.ks` и в `*.prompt`.
- Нет конфигурации/параметров централизованно — параметры передаются через `parameter` скриптов.
